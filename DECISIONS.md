# Decisions

One line each: what was chosen, and why it and not the alternative.

| Decision | Chosen | Why this and not the other |
| --- | --- | --- |
| Shape | One Next.js app on Vercel | Form, panel, agent and webhooks in one deploy and one link; two services would double the setup for no gain in the case. |
| Research agent | eve, one agent with 3 tools | It is the format Paggo's team uses and reads. The AI SDK alone would be one framework less, but a format the reviewers do not use daily. |
| Voice | ElevenLabs Agents, voice on the site | Turn taking, interruptions and latency come solved; building STT + LLM + TTS by hand would spend the time on plumbing instead of the agent. |
| Channel | Browser voice now, phone later | The case says the channel matters less. Web needs no number or WhatsApp approval; the same agent can take calls later. |
| Research flow | The agent follows an order written in its instructions | One path to read and debug. Hard-coded steps before the agent would be a second path doing the same work. |
| Company data | BrasilAPI (Receita mirror) | Free, public, already proven in production. Only works by CNPJ, so the CNPJ comes from the company site first. |
| CNPJ rules | Alphanumeric CNPJ accepted | Valid since July 2026; a digits-only check would reject every company opened after it. |
| Web search | Exa as an explicit tool | Every search lands in the trail with its query and results, which a model's built-in search hides. |
| Structured output | eve `outputSchema` with one Zod schema | The same schema types the voice variables and the panel; the result is validated before it is saved. |
| Trail | `traced()` around every tool, one row per call in `events` | It is the critical criterion: one rule for research and voice, nothing to remember per tool. |
| Database | Postgres, two tables (`leads`, `events`) | The lead keeps form, briefing and conversation as jsonb; a third table would not pay for itself. |
| Database host | Neon Free via the Vercel Marketplace, region iad1 | It fills `DATABASE_URL` in every environment by itself and sits in the same region as the functions; a separate Neon account would mean copying secrets by hand. |
| Research model | Claude Sonnet 5.5, called directly with `ANTHROPIC_API_KEY` | The AI Gateway needs paid credits for this class of model. Against Haiku 5.5 on the same lead it was faster (25 s vs 36 s) and judged better (flagged a test lead, kept to SPICED); Haiku costs a tenth (US$ 0.006 vs 0.056 per briefing), irrelevant at the case's volume. |
| Voice config | JSON and markdown in `voice/`, published by `scripts/voice-sync.mjs` through the REST API | The official agents CLI is deprecated and its Rust successor does not create secrets or webhooks; one short script does all of it, finds everything by name and keeps the prompt a readable file. |
| Voice defaults | `gemini-2.5-flash` with no reasoning, `eleven_v4_turbo`, auth on, one 7-second turn timeout | Fast defaults for a first real call; latency is a high criterion, so the LLM gets measured against 2 or 3 others before it is final. Auth on means no session opens without our token. |
| Voice tests | Text simulations (`scripts/voice-simulate.mjs`) with fictitious personas, mocked agenda tools and fixed transcript checks | Free on the account (0 credits in 20 runs) and done in 25 s, while a voice minute costs about 700 of the few credits left; the checks count the exact errors the real calls showed. |
| Voice LLM | Keep `gemini-2.5-flash`, thinking off, after 4 LLMs in 20 simulations | None of its 55 turns took 1.6 s to the first sentence. `claude-haiku-5-5` never listed modules but left 31% of its turns above 2 s; `gemini-3.5-flash` and `gpt-5-mini` hung up without saying goodbye. Style is fixed in the prompt, latency is not. |
| Agent knowledge | A short block of Paggo facts inside the prompt, from `docs/paggo.md` | The material is small; a retrieval knowledge base would add a lookup to every answer for no gain. |
| Research steps | Site, person search and (for personal e-mail) CNPJ search in parallel; then Receita plus one SPE search | Across 6 hard cases the agent never searched the lead's role or the group's SPEs, the two facts the voice opens with; in parallel they kept the briefing at 23 s on average, sequential steps would add about 5 s each. |
| Registry source | Every CNPJ goes through `lookup_cnpj`; aggregator sites only find the number | Aggregators matched the Receita in the test, but skipping the lookup lost the tax regime, which moves the fit. |
| Lead from Paggo itself | Research Paggo like any company, fit "desconhecido", voice runs a normal conversation | The judges will likely type their own @paggo.com.br e-mail while playing a client; fit "baixo" would mark them out of profile, and "is this a test?" in the voice summary would derail the call they came to judge. |
| Booking guard | The booking route books only a free slot of the search window and refuses anything else | The agent made up a slot in production and in a run despite the prompt; a check in code does not depend on the model. Comparing with every free slot, not only the four offered per day, keeps an offered slot valid if the list moves mid-call. |
| Decision and hang-up rules | On the descriptions of `consultar_agenda` and `end_call`, plus "never hang up because the company looks out of profile" | The rules lived in the prompt, away from the call. A required `quem_decide` field or `end_call`'s spoken message would change the booking or the closing the day before delivery. |
| Critical event question | Asked before the calendar, numbered with the decision question, in the Agenda section and on `consultar_agenda` | The order "impact, critical event, decision" lived in the goals, away from the moment, and the agent skipped it when the lead asked for the meeting (asked in 2 of 6 runs). Next to the decision rule it was asked in 8 of 11; numbering keeps one question from taking the other's place, which a first wording did. |
| Call summary | Our own `resumo` collected field, with the ElevenLabs summary as the fallback | Their fixed summary of a production call said a confirmation would go by e-mail, which nothing sends, and the agent config cannot steer it; a field with our rule fixes the record without touching the conversation. |
| Fit in the voice | The voice does not get the fit; the team filters by fit in the panel | A wrong fit from research (homonym, another company's CNPJ) would end a good call; passing the fit with a prompt rule is for after the case. |
| Fit out of `forAgent` | The research instructions keep the fit out of the voice summary, checked by the eval; the voice prompt ignores any fit it still finds | On 20/10 the summary carried "Fit baixo" and the agent told the lead the company did not fit and hung up. Fixing the source is certain; the prompt line is a second layer, since simulations never reproduced the hang-up. |
| Tech lead | Whoever runs the finance systems or integrations is a lead (Paggo's Influenciador Técnico) and goes to the briefing's hook; "who is the right person" at most once | A tech lead was taken for the wrong person and asked twice in production; Paggo's own role list counts tech as an influencer of the purchase. |
| Panel refresh | The lead page re-reads itself every 5 s while a lead under an hour old has no call | The post-call record lands about 80 s after the call and the panel looked empty; a websocket or polling API would be more parts for the same result. |
| Module hint | `forAgent` names 1 or 2 Paggo modules from a signal table (many SPEs, sells off-plan, many suppliers) | The voice may cite one module after a pain; picking it from research beats the voice guessing mid-call. Marked as a hint, never a fact about the lead. |
| Price in the briefing | No pricing rule anywhere in the briefing; a lead who asks only gets "ele quer saber valores" | Neither Paggo's deck nor its site says how it charges, and the model invented "depends on the number of CNPJs/SPEs". The fix lives in the instructions, and a seventh eval case plus a check on every case proves it, rather than a regex in the app. |
| Research eval | `eve eval` over the hard cases (7 since 19/10) with live tools and deterministic checks (CNPJ, fit, tools called, no partner names), no LLM judge | Stubbed tools would test a fake web; the failures that mattered were facts and skipped tools, which plain checks catch for US$ 0.39 a run, while a judge adds cost and noise. |
| Migrations | `db/schema.sql` run before each build | Idempotent `create if not exists`; no migration tool for two tables. |
| Calendar | Behind an interface, with a fake until the real one arrives | The whole flow runs today; switching is two environment variables. |
| Voice | Samuel, a male Brazilian conversational voice already in Paggo's account, with a masculine prompt | Approved by ear in the production call. Eduardo, the library voice of the tests, would need voices write permission on Paggo's key; Matheus, the calmest one there, is refused by agents for live moderation. |
| Agenda options | Per business day, up to two morning and two afternoon slots; no date parameter | In the first production call the agent made up a slot when the lead asked for another day. A list it can pick from removes the need to invent, and a date parameter would rely on the model's date math. |
| Meeting invite | The goodbye says day, time and "with Paggo's team"; no invite is promised | The case calendar is fictitious and only books the slot (two test bookings sent nothing). Sending our own invite would need a verified e-mail domain the day before delivery, for something no criterion judges. |
| Promises of team action | The agent says "deixo anotado para o time", never that someone will send, call or confirm | Nothing notifies the team: requests live in `duvidas` on the panel. Making the promise true needs e-mail or a CRM, the same barrier as the invite. |
| Form | A single "Nome completo" field, Paggo's own role list with its buying-committee persona, a required consent and a honeypot; no segment or pain fields | The voice skips the role question and the panel speaks the persona language of Paggo's CRM; segment and pain are what research and conversation discover, so asking them adds friction. Each lead costs a paid research, so bots are stopped first. |
| Lead origin | utm_* tags and the referring site in hidden fields filled in the browser, stored as `form.origin`, shown on the panel; no cookie | Serves the GTM role (cost per lead by channel, the first thing marketing and a CRM ask), not a judged criterion of the case: built by choice and kept out of research and voice. Reading only the submit's Referer would lose the referring site; an analytics tool would not tie to the lead and GA4 needs cookie consent. |
| UI theme | Dark by default with a switch to light kept in the browser; one typeface (Outfit), monospace only for raw JSON | Dark is closer to the graphite blocks of Paggo's deck and light stays one click away; following the system theme would open light for most visitors. |
| Panel access | One password via browser basic auth | It holds lead data, but a login system would be over-engineering for the case. |
| Research timing | Runs after the response (`after()`), the page polls every 2 s | The lead sees the waiting page at once; polling needs no open connection on Vercel. |
| Agent context | `AGENTS.md` as the single source, `CLAUDE.md` imports it, `docs/STATUS.md` as running state | Every coding agent reads the same rules; a state file in the repo survives sessions and tools, a tool's private memory does not. |
